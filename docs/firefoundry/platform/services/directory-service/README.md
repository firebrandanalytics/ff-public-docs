# Directory Service

## Overview

The Directory Service is a permissioned document namespace for FireFoundry. It organizes documents into **drives**, **folders**, and **items**, and enforces per-item access control — but it does not own the documents themselves. A file item is always a *pointer* to content that lives elsewhere: a blob in object storage or a Context Service working memory. The service also offers delegated, read-only import from Microsoft 365 (SharePoint and OneDrive, via Microsoft Graph) and Box, so documents a person can already see in those systems can be brought into a FireFoundry drive under that person's own credential.

It is a Go service with a JSON REST API, backed by PostgreSQL for the catalog and by Azure Blob Storage (or a local directory, for development) for the bytes it writes.

## Purpose and Role in Platform

Agent bundles produce documents as working memories, and working memories are local to the application that created them. A report generated by one application cannot, on its own, be browsed or selected by another. The Directory Service gives those documents a shared, permissioned namespace **without copying them per consumer**:

- **Share by reference** — `items:promote` registers an existing blob or working memory as a directory item. Nothing is copied; the same bytes become visible to another application the moment a grant exists.
- **Folder-level permissions** — users are granted `reader`, `writer`, or `owner` on folders, and everything beneath inherits.
- **Application blast-radius gate** — every calling application must also be granted access to the drive, so an application can never reach a drive it was not given, whichever user it claims to act for.
- **Bring in external content** — a signed-in person connects their Microsoft 365 or Box account, browses it, and imports a file or folder into a drive. Import copies bytes once, at ingest; every consumer then shares that single copy.

## Key Features

- **Drives, folders, files** — hierarchical namespace with materialized paths, path lookup, keyset-paged listings, rename with `If-Match` optimistic concurrency, and soft-delete (trash)
- **Dual-grant authorization** — every read or write requires both an application grant on the drive root and (when a user is asserted) a user grant on the item's ACL anchor
- **Anchor-based ACLs** — grants attach to folders; descendants inherit; `entry-points` tells a user where they can start browsing when they cannot see the drive root
- **No existence leaks** — items a caller cannot reach answer `404`, never `403`
- **Content by reference** — promote existing blobs or working memories; trashing an item never deletes content
- **Content-addressed uploads** — uploaded and imported bytes are stored at `directory/<driveId>/<sha256>`
- **Delegated connections** — OAuth consent per (application, user) pair; refresh tokens sealed at rest with AES-256-GCM and never returned by the API
- **Microsoft Graph and Box import** — browse the source, then run a background import job with per-entry state, retries, and counts-by-state progress
- **Re-import by ETag** — re-importing the same source skips unchanged files and refreshes changed ones in place
- **Optional entitlement check** — the `/v1` surface can be gated on the `directory.access` entitlement, in `report` (default) or `enforce` mode

## Architecture Overview

```
   Agent bundles / applications                      Browser (consenting user)
   X-API-Key + X-On-Behalf-Of                                    │
              │                                                  │ OAuth redirect
┌─────────────▼──────────────────────────────────────────────────▼───────┐
│                        HTTP API (Go net/http)                          │
│  /health /ready   ·   /v1 catalog   ·   /v1/connections   ·  /v1/imports│
│  API-key resolution → optional entitlement guard (directory.access)    │
└──────────────┬──────────────────────────────┬──────────────────────────┘
               │                              │
┌──────────────▼───────────────┐  ┌───────────▼──────────────────────────┐
│   Directory domain service   │  │   Token broker + connectors          │
│   dual-grant authorization   │◄─┤   sealed refresh tokens (AES-GCM)    │
│   drives · items · grants    │  │   Microsoft Graph reader · Box reader│
└──────────────┬───────────────┘  └───────────┬──────────────────────────┘
               │                              │
               │   ┌──────────────────────────▼───────────┐
               │   │   Import workers (IMPORT_WORKERS)    │
               │   │   enumerate → fetch → settle         │
               │   └──────┬───────────────────────┬───────┘
               │          │                       │
┌──────────────▼──────────▼───────┐   ┌───────────▼──────────────────────┐
│  PostgreSQL (schema: directory) │   │  Blob storage                    │
│  drive · item · acl_entry       │   │  Azure Blob or local directory   │
│  connection · import_job/entry  │   │  directory/<driveId>/<sha256>    │
└─────────────────────────────────┘   └──────────────────────────────────┘
```

**Core components:**

- **HTTP API** — 15 catalog routes, 14 connection/import routes, and two unauthenticated probes. When connections are not configured, the connection and import routes answer `503 CONNECTIONS_NOT_CONFIGURED` and the catalog is unaffected.
- **Directory domain service** — the single authorization path. Every drive and item access, including everything the importer writes, goes through its dual-grant check.
- **Token broker** — the only component that holds OAuth credentials. Browse and import name a *connection*, never a token; refreshes are serialized per connection.
- **Connectors** — read-only Microsoft Graph and Box readers. There is no write-back to the source system.
- **Import workers** — background goroutines in the same process that claim jobs with leases, so several replicas can share the work.

## Version and Maturity

- **Status**: Preview. The catalog, the authorization model, and delegated read-only import are implemented. There is no tagged release yet; `GET /health` reports the build commit when `BUILD_COMMIT` is set.
- **Microsoft 365 (Graph)**: supported for delegated browse and import.
- **Box**: implemented on the same connection-bound browse/import engine, but validated only against a controlled test environment that mimics the Box API — it has not yet been validated against live customer Box accounts. Treat Box as early access and validate against your own Box tenant before relying on it.
- **Not yet available**: move (only rename is implemented), trash purge/retention, delta sync or change notifications, write-back to Microsoft 365 or Box, renditions.
- **Packaging**: the service is not yet part of the FireFoundry Helm charts. See [Operations](./operations.md#deployment).
