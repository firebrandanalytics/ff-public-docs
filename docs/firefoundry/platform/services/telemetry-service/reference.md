# Telemetry Service — Reference

Complete reference for the Telemetry Service's ingestion RPC, HTTP endpoints, error behavior, and configuration.

| Interface | Default port | Protocol |
|-----------|--------------|----------|
| Ingestion API | `50051` | Connect RPC (Protobuf service, HTTP/1.1; Connect and gRPC-Web wire protocols) |
| Query, health, and admin API | `3000` | HTTP/JSON |

None of the ingestion or query endpoints require authentication; they are intended to be reachable only inside the cluster. The only protected endpoint is the admin maintenance endpoint.

An OpenAPI 3.1 description of the HTTP API is served by the running service at `/openapi`.

The **Since** column below gives the service version that introduced each item.

## Ingestion API

Package `firefoundry.telemetry.v1`, service `TelemetryIngestionService`.

| RPC | Path | Since |
|-----|------|-------|
| `IngestBatch(IngestBatchRequest) returns (IngestBatchResponse)` | `POST /firefoundry.telemetry.v1.TelemetryIngestionService/IngestBatch` | 0.1.0 |

The server speaks the Connect protocol over HTTP/1.1, so use a Connect client (`createConnectTransport`) or a gRPC-Web client, or send JSON directly with `Content-Type: application/json`. Clients that require native gRPC over HTTP/2 are not supported by the current server.

### IngestBatchRequest

| Field | Type | Description |
|-------|------|-------------|
| `events` | `repeated TelemetryEvent` | Events to ingest. Maximum `MAX_BATCH_SIZE` (default 100) per request. |

### TelemetryEvent

| # | Field | Type | Required | Description |
|---|-------|------|----------|-------------|
| 1 | `event_id` | string | Recommended | UUID. Generated by the service if empty. |
| 2 | `trace_id` | string | No | Trace identifier shared across a run. |
| 3 | `span_id` | string | No | Span identifier. |
| 4 | `parent_span_id` | string | No | Parent span identifier. |
| 5 | `layer` | string | Yes | Event kind within the producer, e.g. `BotRequest`, `LLMResponse`, `BrokerRequest`. |
| 6 | `service` | string | Yes | Producing service name. |
| 7 | `environment` | string | No | Environment label, e.g. `production`. |
| 8 | `error` | bool | No | Marks the event as an error for filtering. |
| 9 | `payload` | bytes | Yes | UTF-8 JSON document (raw JSON bytes, base64 in the JSON encoding). |
| 10 | `created_at_ms` | int64 | No | Unix milliseconds. Defaults to ingestion time. |
| 11 | `meta` | bytes | No | Optional UTF-8 JSON object stored as-is. |
| 12 | `partition_key` | optional string | No | Monday (UTC) of the event's week, `YYYY-MM-DD`. Must match `created_at_ms` if set. Since 0.3.0. |

### IngestBatchResponse

| Field | Type | Description |
|-------|------|-------------|
| `ingested_count` | int32 | Number of events accepted. |
| `root_hashes` | `repeated bytes` | One 32-byte BLAKE3 root hash per request event, in request order. Failed events get 32 zero bytes. |
| `errors` | `map<int32, string>` | Per-event error messages keyed by index in the request. Only failed events appear. |

An accepted event has been validated, shredded, and queued for the next batch flush. It is persisted asynchronously (see [Concepts → Ingestion Lifecycle](./concepts.md#ingestion-lifecycle)).

### Ingestion Errors

| Condition | Result |
|-----------|--------|
| More events than `MAX_BATCH_SIZE` | Whole request fails with Connect code `invalid_argument`: `Batch size N exceeds maximum of M` |
| Payload larger than `MAX_PAYLOAD_BYTES` | Per-event error: `Payload size N bytes exceeds maximum of M bytes` |
| Payload is not valid JSON | Per-event error: `Invalid JSON payload` |
| Payload nested deeper than `MAX_JSON_DEPTH` | Per-event error: `JSON depth N exceeds maximum of M` |
| `partition_key` malformed or not a Monday | Per-event error, e.g. `partition_key must be a Monday in UTC` |
| `partition_key` does not match `created_at_ms` | Per-event error: `partition_key X does not match created_at week Y` |

### Query RPCs (Defined, Not Served)

The proto file also declares a `TelemetryQueryService` with `GetEvent`, `ListEvents`, and `GetEventsByTrace`. These RPCs are **not registered** by the current server; use the HTTP query API below instead.

## HTTP Query API

### GET /events

List event metadata (no payloads). Since 0.1.0.

| Query parameter | Type | Default | Description |
|-----------------|------|---------|-------------|
| `trace_id` | string | — | Return events for this trace, oldest first. When set, `service`, `layer`, `error`, and `offset` are ignored. |
| `service` | string | — | Filter by producing service. |
| `layer` | string | — | Filter by layer. |
| `error` | `true` | — | When `true`, return only error events. |
| `limit` | number | `50` | Maximum results; capped at `100`. |
| `offset` | number | `0` | Number of results to skip (filtered listing only). |
| `partition_key` | `YYYY-MM-DD` | — | Restrict to one week (Monday UTC). Since 0.3.0. |

Filtered listings are ordered newest first. Response `200`:

```json
{
  "events": [
    {
      "partitionKey": "2026-06-29",
      "eventId": "6b1f0d52-6f0e-4a7e-9d0a-2f0a3f8b9c11",
      "traceId": "trace-7f3a",
      "spanId": "span-2",
      "parentSpanId": "span-1",
      "layer": "LLMResponse",
      "service": "ff-broker",
      "environment": "production",
      "error": false,
      "payloadSize": 18234,
      "nodeCount": 37,
      "createdAt": "2026-06-30T14:02:11.482Z",
      "rootHash": "ab45…64 hex chars…",
      "meta": null
    }
  ],
  "count": 1,
  "offset": 0,
  "limit": 50
}
```

### GET /event/{eventId}

Return one event with its fully reconstructed payload. Since 0.1.0.

| Parameter | In | Description |
|-----------|----|-------------|
| `eventId` | path | Event UUID. |
| `partition_key` | query | Optional week to search. Since 0.3.0. |

Response `200`:

```json
{
  "event": { "partitionKey": "…", "eventId": "…", "traceId": "…", "spanId": "…", "parentSpanId": null,
             "layer": "…", "service": "…", "environment": null, "error": false,
             "payloadSize": 1234, "nodeCount": 5, "createdAt": "…", "meta": null },
  "payload": { },
  "reconstruction": { "nodesFetched": 5, "durationMs": 1.7, "cached": false }
}
```

The `event` object has the same fields as a `/events` item except `rootHash`. `reconstruction.nodesFetched` is `0` when the document was served from cache.

| Status | Meaning |
|--------|---------|
| `404` | `{"error":"Event not found"}` |
| `400` | Invalid `partition_key` |
| `500` | Lookup or reconstruction failed (including a malformed, non-UUID `eventId`) |
| `503` | Service still initializing |

### POST /events/batch

Return several events with their reconstructed payloads in one request. Since 0.2.0.

Request body:

```json
{
  "eventIds": ["6b1f0d52-…", "0c3e9a11-…"],
  "partitionKey": "2026-06-29"
}
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `eventIds` | string[] | Yes | Event UUIDs to fetch. |
| `partitionKey` | string | No | Restrict every lookup to one week (since 0.3.0). |

Response `200`: `{ "results": [ <same shape as GET /event/{id}> | null, ... ] }`, in the same order as `eventIds`. Missing events are `null`.

| Status | Meaning |
|--------|---------|
| `400` | `eventIds must be an array of strings`, or invalid `partitionKey` |
| `500` | Lookup or reconstruction failed |
| `503` | Service still initializing |

### GET /doc/{rootHash}

Diagnostics: reconstruct a stored document directly from its root hash (64 hex characters, as returned in `rootHash`). Optional `partition_key` query parameter.

Response `200`: `{ "document": <JSON>, "nodeCount": 5, "durationMs": 1.2, "cached": false }`. Returns `400` for a hash that is not 32 bytes, `404` if the document is not found.

## Utility and Diagnostics Endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/health` | Liveness. Always HTTP `200`; body `status` is `healthy` only when the service is ready and the database responds. |
| GET | `/ready` | Readiness. `200 {"status":"ready"}` when running and the current and next weekly partitions exist; otherwise `503 {"status":"not ready","state":"…"}`. |
| GET | `/metrics` | Prometheus text-format metrics (see [Operations → Monitoring](./operations.md#monitoring)). |
| GET | `/info` | `{ service, version, environment, shredStrategy }` from configuration. |
| GET | `/batch/stats` | Pending batch contents: `{ nodeCount, objEdgeCount, arrEdgeCount, eventCount, flushing }`. |
| GET | `/cache/stats` | Document cache: `{ entries, sizeBytes, maxSizeBytes }`. |
| GET | `/openapi` | OpenAPI documentation for the HTTP API. |

`/health` example:

```json
{
  "status": "healthy",
  "service": "ff-telemetry-shredder",
  "version": "0.1.0",
  "uptime": 842113,
  "checks": { "database": true }
}
```

`version` in `/health` and `/info` reports the `SERVICE_VERSION` setting, not the image version.

## Admin Endpoint

### POST /admin/partitions/maintain

Run weekly partition maintenance in-process: provision current and future weeks, drop fully expired weeks, and truncate expired legacy data. Since 0.3.0.

**Authentication:** disabled (returns `404`) unless `PARTITION_MAINTENANCE_API_KEY` is set. Present the key as `X-API-Key: <key>` or `Authorization: Bearer <key>`.

| Query parameter | Default | Description |
|-----------------|---------|-------------|
| `dry_run` | `true` | `false` (or `0`) performs a live run. Values other than `true`/`false`/`1`/`0` return `400`. |
| `provision_only` | `false` | `true` (or `1`) provisions current and future weeks only — no drops, no legacy truncation. `retention_days` is ignored. |
| `retention_days` | `PARTITION_RETENTION_DAYS` (30) | Positive integer. Whole weeks entirely older than this are dropped. |
| `future_weeks` | `PARTITION_FUTURE_WEEKS` (4) | Positive integer. Number of future weeks to provision. |

The endpoint connects with the migration (admin) credentials, not the runtime roles. Response body (`200` or `500`):

```json
{
  "dryRun": true,
  "provisionOnly": false,
  "retentionDays": 30,
  "futureWeeks": 4,
  "created": ["2026-07-27"],
  "dropped": ["2026-05-18"],
  "legacyTruncated": false,
  "failures": []
}
```

| Status | Meaning |
|--------|---------|
| `200` | Run completed (or dry-run computed) with no failures |
| `400` | Invalid query parameter |
| `401` | Missing or wrong API key |
| `404` | Endpoint not enabled |
| `500` | Run completed but some weeks could not be dropped (listed in `failures`) |
| `503` | Could not run (migration credentials missing or database unreachable) |

## Error Response Format

HTTP errors use a single shape:

```json
{ "error": "partition_key must be a Monday in UTC" }
```

Common `partition_key` errors (`400`): `partition_key must use YYYY-MM-DD format`, `partition_key is not a valid date`, `partition_key must be a Monday in UTC`.

## Environment Variables

### Service

| Variable | Default | Description |
|----------|---------|-------------|
| `PORT` | `3000` | HTTP port (query, health, admin). |
| `GRPC_PORT` | `50051` | Ingestion (Connect RPC) port. |
| `NODE_ENV` | `development` | `development`, `production`, or `test`. |
| `LOG_LEVEL` | `info` | `debug`, `info`, `warn`, or `error`. |
| `SERVICE_NAME` | `ff-telemetry-shredder` | Name reported in logs, `/health`, `/info`, and metrics. |
| `SERVICE_VERSION` | `0.1.0` | Version string reported in `/health`, `/info`, and metrics. |

### Database

| Variable | Default | Description |
|----------|---------|-------------|
| `PG_HOST` | `localhost` | PostgreSQL host. |
| `PG_PORT` | `5432` | PostgreSQL port. |
| `PG_DATABASE` | `telemetry` | Database name. |
| `PG_READ_USER` | `fireread` | Reader role (queries). |
| `PG_PASSWORD` | — | Password for the reader role. |
| `PG_WRITE_USER` | `fireinsert` | Writer role (ingestion). |
| `PG_INSERT_PASSWORD` | — | Password for the writer role. |
| `PG_DDL_USER` | `fireddl` | Create-only DDL role used by the partition provisioner. Since 0.5.0. |
| `PG_DDL_PASSWORD` | empty | Password for the DDL role. Empty disables in-service provisioning. Since 0.5.0. |
| `PG_SSL_DISABLED` | `false` | `true` disables TLS to PostgreSQL (in-cluster databases); otherwise TLS is required. |

Each of the reader and writer pools holds up to 10 connections.

### Ingestion Limits

| Variable | Default | Description |
|----------|---------|-------------|
| `MAX_BATCH_SIZE` | `100` | Maximum events per `IngestBatch` request. |
| `MAX_PAYLOAD_BYTES` | `10485760` (10 MB) | Maximum payload size per event. |
| `MAX_JSON_DEPTH` | `100` | Maximum JSON nesting depth per payload. |

### Shredding and Batching

| Variable | Default | Description |
|----------|---------|-------------|
| `SHRED_STRATEGY` | `size:1024` | `full`, `depth:N`, or `size:N` (see [Concepts](./concepts.md#shred-strategies)). |
| `BATCH_SIZE` | `1000` | Flush after this many queued events. |
| `BATCH_FLUSH_INTERVAL_MS` | `1000` | Flush timer interval. |
| `BATCH_MAX_WAIT_MS` | `5000` | Flush when pending data has waited this long. |

### Partitions and Maintenance

| Variable | Default | Description |
|----------|---------|-------------|
| `PARTITION_PROVISIONER_ENABLED` | `true` | Set to `false` to disable the in-service provisioner. Since 0.4.0. |
| `PARTITION_PROVISIONER_INTERVAL_MS` | `3600000` | Provisioner interval (hourly). Since 0.4.0. |
| `PARTITION_RETENTION_DAYS` | `30` | Default retention for maintenance runs. |
| `PARTITION_FUTURE_WEEKS` | `4` | Default number of future weeks to provision. |
| `PARTITION_MAINTENANCE_API_KEY` | empty | Enables `POST /admin/partitions/maintain` when set. |
| `MIGRATION_DATABASE_URL` | — | Full admin connection URL for migrations and maintenance. Overrides the variables below. |
| `MIGRATION_DB_USER` | `firebrand` | Admin role for migrations and maintenance. |
| `MIGRATION_DB_PASSWORD` | — | Admin role password. |

### Accepted but Not Currently Applied

These variables are parsed (and set by the Helm chart) but do not change behavior in the current release:

| Variable | Note |
|----------|------|
| `CACHE_ENABLED` | The document cache is always enabled. |
| `CACHE_MAX_SIZE_MB` | The document cache is fixed at 256 MB per replica. |
| `CACHE_TTL_SECONDS` | Not used; entries are evicted by LRU only. |
| `METRICS_ENABLED` | `/metrics` is always served. |
